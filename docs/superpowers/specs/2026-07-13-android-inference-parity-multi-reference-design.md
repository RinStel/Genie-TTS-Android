# Android Inference Parity And Multi-Reference Design

## Goal

Restore Android inference behavior to the Python implementation closely enough that text prosody, reference timbre, and semantic decoding can be compared stage by stage, then add GPT-SoVITS-compatible auxiliary reference audio for V2ProPlus without regressing background or repeated-generation performance.

## Scope

This work covers:

- deterministic Python/Android parity fixtures for preprocessing and model boundaries;
- the predefined `Normal` reference selection contract;
- separate synthesis and prompt languages;
- Chinese normalization, G2P, tone sandhi, erhua, and RoBERTa alignment;
- high-quality reference-audio decoding and resampling;
- semantic-token slicing parity;
- precision-safe reference conditioning when QNN is selected;
- complete V2ProPlus multi-reference model export and Android execution;
- GUI and `POST /infer` support for auxiliary reference audio;
- caching and measurements required to preserve repeated-generation performance.

XNNPACK remains out of the active runtime path. V2 models continue to use one reference because the complete multi-reference interface applies to V2ProPlus.

## Compatibility Baseline

The Python implementation is the behavioral baseline. Tests must record, for fixed text and audio fixtures, the following boundaries:

1. normalized synthesis and prompt text;
2. phone ids, `word2ph`, and BERT features;
3. 32 kHz and 16 kHz reference PCM;
4. HuBERT output and speaker embedding;
5. prompt-conditioning outputs;
6. T2S encoder outputs;
7. generated semantic-token count and values;
8. vocoder input shapes and generated audio length.

Numerical comparisons use exact equality for integer tensors and explicit tolerances for float tensors. A backend-specific tolerance must be documented by the test that uses it; failures must not silently fall back to zero features.

## Reference Selection And Languages

`prompt_wav.json` must be parsed as JSON and select the `Normal` object explicitly. Audio and text must come from the same object. A malformed or missing `Normal` entry is an error; falling back to the first unrelated emotion is not allowed.

`GenerationRequest` gains a prompt language separate from the synthesis language. Existing callers that omit it use the synthesis language for backward compatibility. The GUI exposes the prompt language next to reference text. HTTP `POST /infer` accepts `promptLanguage`; omission preserves the old behavior.

## Chinese Frontend

Android must no longer claim parity based on a single-character pinyin table. The target pipeline matches the Python ordering:

1. text normalization;
2. sentence splitting and punctuation mapping;
3. lexical segmentation and contextual polyphone resolution;
4. pronunciation overrides;
5. word-aware tone sandhi;
6. erhua merging;
7. OpenCPOP phone conversion;
8. tokenizer-backed RoBERTa expansion through `word2ph`.

Because embedding the Python runtime is inappropriate for Android, portable lexical and contextual resources are generated by a Python build tool and consumed by Kotlin. The generated resources must carry a schema/version marker and reproducible source hashes. A fixture corpus containing polyphones, neutral tones, third-tone chains, numbers, punctuation, and erhua is used to compare Python and Android outputs.

RoBERTa tokenization follows the tokenizer JSON configuration rather than a raw character-to-vocabulary lookup. Any tokenizer, model, shape, or `word2ph` mismatch is surfaced in status/trace output and fails preparation; it must not become an all-zero BERT tensor unnoticed. An explicit missing-RoBERTa configuration may use zero BERT only when both runtimes are intentionally configured that way.

## Reference Audio Fidelity

Reference audio is decoded to mono float PCM without clipping or implicit gain changes. Resampling must use a production-quality band-limited implementation with behavior validated against Python `soxr` HQ fixtures. The same processed 32 kHz audio, including the 0.3-second tail silence, feeds prompt conditioning; its 16 kHz derivative feeds HuBERT and speaker verification.

The implementation should prefer a small native resampler integrated through the existing CMake/JNI layer. It must process audio in bounded memory and expose no Java per-sample allocation path.

## Decoder Parity

The Kotlin and JNI loops use one shared definition of generated-step count and semantic slicing. Each decoder step appends one token, so the helper takes the last `completed_count` tokens, retains a normal token even when the stop flag is set, and truncates at the first special/EOS token. Tests cover normal EOS, EOS on the first generated token, maximum-step termination, and native/array paths. The result passed to the vocoder must match the corrected Python baseline fixture, including explicit terminal-token replacement behavior.

If investigation proves Python's `-idx:` expression itself is off by one, the repository must first add a Python regression test and correct Python and Android together. Android must not preserve a known Python defect merely to make an accidental implementation detail equal.

## QNN Precision And Performance

Selecting QNN does not imply that every auxiliary model runs on HTP. Reference-critical HuBERT, speaker verification, prompt conditioning, and RoBERTa start from CPU ORT settings that reproduce Python numerics. A component may move to QNN only after a parity fixture demonstrates that its output remains within an explicit tolerance and an on-device benchmark demonstrates a useful speed gain.

T2S and vocoder sessions retain QNN acceleration where supported. Provider options are scoped per model role rather than reused globally. Performance measurements report preparation, reference conditioning, decoder, vocoder, and total time separately for cold and warm runs.

## Complete Multi-Reference Model Path

GPT-SoVITS V2ProPlus treats auxiliary references as independent reference spectrograms and speaker embeddings; they do not require prompt text and they are not averaged in Android application code.

The converter gains a versioned multi-reference export path built from the matching GPT-SoVITS V2ProPlus PyTorch model implementation. The primary reference remains the source of prompt text, HuBERT content, and T2S semantic conditioning. When auxiliary references are requested, the exported graph accepts:

- one or more auxiliary reference audios represented by independent dynamic-length inputs plus a count, or another ONNX-safe representation proven equivalent to the upstream list behavior;
- one speaker embedding per reference;
- the existing text and semantic inputs through the surrounding V2ProPlus pipeline.

With no auxiliary references, Android continues to use the legacy single-reference prompt graph. This matches GPT-SoVITS' auxiliary-reference behavior: auxiliary audio has no transcript of its own and supplies independent acoustic conditioning rather than replacing the primary semantic prompt.

The wrapper reproduces upstream list ordering and conditioning operations before export. Export validation compares PyTorch and ONNX outputs for one, two, and three references. Model metadata records the interface version and maximum supported reference count if the graph requires a fixed bound.

The implemented `multi_reference_v1` graph uses a bounded set of independent
dynamic-length input pairs (`ref_audio_N`, `sv_emb_N`) plus a `reference_count`
input. Unused slots are masked inside ONNX before the conditioning tensors are
reduced, so Android never pads variable-length waveforms or averages embedding
outputs in application code.

The existing single-reference `prompt_encoder_fp32.onnx` and `vits_fp32.onnx` remain supported. Android detects model inputs/metadata at initialization:

- multi-reference model: expose and execute auxiliary references;
- legacy model: execute the existing single-reference path and return a clear validation error if auxiliary references were requested.

No silent embedding averaging or waveform concatenation is permitted as a substitute for the complete model path.

## Android Data Flow

`GenerationRequest` carries an ordered list of auxiliary audio paths. Each auxiliary item contains only an audio path; it has no transcript or language field. The primary reference continues to carry audio, transcript, and prompt language because it conditions T2S semantics.

Reference preparation is split into:

- primary semantic conditioning: prompt phones/BERT, HuBERT, speaker embedding, and model reference features;
- per-audio acoustic conditioning: decoded/resampled PCM, spectrogram or exported equivalent, and speaker embedding.

The cache key includes canonical path, size, modification time, model/interface version, preprocessing version, and backend role. Changing one auxiliary file invalidates only that entry. Ordered multi-reference bundles reuse cached entries and avoid recomputing the primary reference across consecutive sentences.

## GUI And HTTP API

The main reference card keeps one primary reference and adds an auxiliary-reference list with add/remove controls. Auxiliary rows show only file names and never request text. File selection uses the existing app-scoped copy mechanism. The interface caps the number of references at the model-declared limit and hides or disables auxiliary controls for legacy/V2 models with a concise explanation.

`POST /infer` adds:

```json
{
  "promptLanguage": "zh",
  "auxReferenceAudioPaths": ["/path/aux-1.wav", "/path/aux-2.wav"]
}
```

Both fields are optional. Existing requests remain valid. Validation rejects blank paths, duplicates, missing files, unsupported model variants, and counts above the model limit before inference starts.

## Error Handling And Observability

Preparation errors identify the failing boundary: JSON reference selection, G2P, tokenizer, RoBERTa, audio decoding, resampling, speaker embedding, multi-reference capability, or model execution. Trace logs include tensor shapes, cache hit/miss status, backend assignment per model role, and elapsed time, but not raw user text or audio samples.

## Performance Acceptance

Performance work must not change reference-condition outputs merely to reduce latency. Acceptance uses the same phone/semantic/audio fixture before and after optimization.

For repeated synthesis with unchanged primary and auxiliary references:

- all reference text, audio, HuBERT, speaker, and multi-reference conditioning caches must hit;
- preparation performs only synthesis-text frontend work;
- no model session is recreated;
- background execution remains in the foreground service with the existing wake-lock policy;
- warm-run timing must not regress by more than 5% on the same device/backend unless a measured quality fix requires it and the trade-off is documented.

## Testing And Delivery

Each implementation task follows test-first development and receives an independent spec/quality review before the next task. Required verification includes Python tests, Android unit tests, Android debug assembly, ONNX model validation, and a device-side comparison script that captures stage hashes, tolerances, and timings.

Large generated models and external weights are not committed. The converter, metadata, fixtures small enough for source control, and reproducible export instructions are committed.
